# Model Risk Management (MRM) policy — Tradebot v1.0

Compliance framework that gates every model from research → live.

## 1. Scope

Every artefact produced by Stage 3 (`apps/train_cpcv`) and packaged for
`apps/live_trader` is in scope. The policy covers:

- the trained `*.joblib` model
- its calibrator (Platt per CPCV path)
- the feature pipeline configuration (hash-pinned)
- the strategy YAML and risk YAML at deploy time

## 2. Three-tier promotion

```
research ──► staging ──► production
  ▲             │             │
  └────────[ rollback ]──────┘
```

| Tier        | Allowed activity              | Gate to next tier                       |
|-------------|-------------------------------|-----------------------------------------|
| research    | unrestricted notebook work    | training-time green CI                  |
| staging     | shadow trading via PaperOMS   | ≥ 14 days shadow + DM-test PROMOTE      |
| production  | live order placement          | MRM report signed; circuit breaker armed|

The `live.mode=live` flag in `conf/env/prod.yaml` is locked off until
the MRM report exists and `approved_by` is populated.

## 3. MRM report — nine mandatory sections

Generated by `tradebot.compliance.generate_mrm_report`:

1. **Model identity** — `git_sha`, `feature_hash`, `dvc_hash`, training date.
2. **Data provenance** — list of source parquets, date ranges, n_bars/symbol.
3. **Validation method** — CPCV fold structure, embargo, purge mechanism.
4. **Performance metrics** — OOS Sharpe, DSR, max-DD, Calmar, ECE per fold.
5. **Stress test results** — 4 historical scenarios + Monte Carlo (3-sigma).
6. **Lookahead audit** — which guards ran, which baselines, results.
7. **Risk management** — Kelly fractions, position limits, DD breakers.
8. **Limitations** — regimes not seen, fragility flags.
9. **Governance** — manual approval line; date + name.

## 4. Champion / Challenger statistical test

Before promotion the `ChampionChallenger.evaluate(champion_pnl, challenger_pnl)`
runs the Diebold-Mariano test on per-bar loss differentials with the
Harvey-Leybourne-Newbold small-sample correction. A `PROMOTE` recommendation
requires **both**:

```
p_value(DM, two-sided) < 0.05
AND
Sharpe(challenger) − Sharpe(champion) > 0.05
```

If either fails, the challenger is held; the champion stays in production.

## 5. Stress-test requirements

`tradebot.risk.stress_test.StressTestSuite` runs four mandatory historical
scenarios:

| Scenario          | Window                  | Asset relevance        |
|-------------------|-------------------------|------------------------|
| COVID crash       | 2020-02-20 → 2020-03-13 | BTC, ETH (-50 % week)  |
| Luna collapse     | 2022-05-04 → 2022-05-14 | BTC, ETH, SOL contagion|
| FTX collapse      | 2022-11-06 → 2022-11-11 | BTC -25 % in 5 days    |
| Fed rate shock    | 2022-01-01 → 2022-06-18 | macro bear regime      |
| Synthetic 3 σ MC  | n=10 000 Monte Carlo    | tail-risk verification |

A model whose backtested drawdown in any historical scenario exceeds
**1.5 × the live circuit-breaker drawdown threshold** (default 12 %) is
refused promotion.

## 6. Lookahead guards (hard CI gate)

The `tests/lookahead/` suite must remain green for the candidate model. A
single failing test in any of:

- `test_macro_lag.py`
- `test_cusum_causal.py`
- `test_featurestore_fence.py`
- `test_triple_barrier_embargo.py`
- `test_regime_causal.py`
- `test_oms_audit_completeness.py`

blocks promotion. Re-run after fixing the offending feature.

## 7. Periodic re-attestation

| Cadence   | Action                                                         |
|-----------|----------------------------------------------------------------|
| daily     | drift-monitor, position report, circuit-log review              |
| weekly    | TCA report, PR review of any registry promotion                 |
| monthly   | impact-coefficient re-calibration (`apps/calibrate_impact.py`)  |
| quarterly | full MRM report regeneration; sign-off                          |
| ad-hoc    | post-incident review: SEV-1 or SEV-2 from `runbook.md`          |

The quarterly MRM regeneration is mandatory even if the model has not
changed — re-attestation is a checkpoint, not just a release gate.

## 8. Roles

| Role                 | Responsibility                                          |
|----------------------|---------------------------------------------------------|
| Chief Quant Architect| Designs MRM template, approves stress scenarios.        |
| Head of Research     | Signs off challenger promotions, owns lookahead suite.  |
| Engineering on-call  | Runs runbook, owns infra (Wave 10–11).                  |
| Compliance officer   | Verifies MRM report completeness before production.     |

All sign-offs are recorded in `artefacts/governance/sign_off_log.jsonl`
(append-only).

## 9. Incident reporting

Any SEV-1 or SEV-2 event from `docs/runbook.md` triggers a 24h-deadline
incident report. The report goes into the next MRM update under §9
(Governance).
